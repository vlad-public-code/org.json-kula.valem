# @valem/embed

Embed a single **live, interactive Valem model** into any web page or React app.

A Valem model is a declarative spec that computes on the server — derived values, constraints and
effects recompute reactively as inputs change. `@valem/embed` drops one into your page as an
interactive widget: the viewer edits inputs and watches everything recompute, with no spreadsheet and
no backend of your own.

There are two ways to embed, sharing one payload:

1. **A copy-paste `<iframe>`** — works in any HTML host (a blog, Notion, a CMS). Generate it from the
   Valem sandbox's **Share → Embed** dialog; no npm needed.
2. **This package's `<ValemModel>` React component** — mounts natively in a React tree with
   callbacks, theming, and auto-height.

Both point at a Valem sandbox origin (the public sandbox by default), which loads the spec and
computes against it. Each viewer gets a **private, ephemeral copy** — their edits are never saved or
shared back to you or to other viewers.

## Install

```bash
npm install @valem/embed
```

`react` and `react-dom` (v18+) are peer dependencies.

## Usage

### From an inline spec

```tsx
import { ValemModel } from '@valem/embed';

const mortgageSpec = { /* a Valem ModelSpec object */ };

export function Calculator() {
  return <ValemModel spec={mortgageSpec} height="auto" />;
}
```

### From a share fragment (generated by the sandbox Embed dialog)

```tsx
<ValemModel embedRef="1.q7Fh…" mode="interactive" theme="auto" />
```

### Reading state back

```tsx
<ValemModel
  spec={orderBuilderSpec}
  onChange={(state) => console.log('current model state', state)}
  onConstraintFlag={(violations) => setErrors(violations)}
  onReady={() => console.log('embed ready')}
/>
```

## Props

| Prop | Type | Default | Notes |
|---|---|---|---|
| `spec` | `object` | — | Inline model spec. Provide this **or** `embedRef`. |
| `embedRef` | `string` | — | A pre-encoded share fragment from the Embed dialog. |
| `mode` | `'interactive' \| 'readonly'` | `'interactive'` | `readonly` renders a computed, non-editable snapshot. |
| `theme` | `'light' \| 'dark' \| 'auto'` | `'auto'` | `auto` follows the viewer's OS preference. |
| `endpoint` | `string` | public sandbox | The Valem sandbox origin to compute against. |
| `height` | `number \| 'auto'` | `480` | `'auto'` sizes the frame from its content. |
| `attribution` | `boolean` | `true` | Show the "Powered by Valem" footer. |
| `view` | `string` | spec default | Initial view id to open. |
| `lazy` | `boolean` | `true` | Defer creating the model until the component scrolls into view. |
| `onReady` | `() => void` | — | Fired once the model is live. |
| `onChange` | `(state) => void` | — | Fired on every state change. |
| `onConstraintFlag` | `(violations) => void` | — | Fired when constraints flag after a mutation. |
| `onError` | `(message) => void` | — | Fired if the model fails to load. |

## How it works

`<ValemModel>` renders the sandbox's `/embed.html` route in a sandboxed `<iframe>`
(`allow-scripts allow-forms allow-same-origin`, `loading="lazy"`). The spec travels in the URL
fragment (never sent to a server as a URL), and the embed page forks a fresh, throwaway server model
from it. The component listens for `postMessage` events from the frame — validating they come from
the embed origin — and translates them into the `onReady` / `onChange` / `onConstraintFlag` callbacks
and auto-height. It defers creating the model until it scrolls into view (`lazy`, on by default), and
asks the frame to dispose its server model when the component unmounts.

Privacy: a `spec` or `embedRef` that carries entered data is readable by anyone who can see the page.
Share spec-only unless you intend the data to be public.
